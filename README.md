## How to Add a Publication

The whole Annexes website is built around PDFs, so new publications will need to upload a PDF to trigger the full workflow.

### Step 1: Prepare your PDF

Add metadata (title, authors, date, keywords) to your PDF. 
You can do it [At this link 🔗](https://pdf.metadata.care/online-editor/)
The system reads the metadata automatically.
If the PDF **has no metadata**, the filename becomes the title and you will be able to edit things right after.

### Step 2: Upload the PDF

You have two ways to do this:

**Option A — Use GitHub's interface:**
1. Go to [PDF Folder 📁]([https://github.com/medialab/editions-annexes](https://github.com/medialab/editions-annexes/tree/c398bb0044c467a76d181a520c3812cb45e0ef6b/static/pdfs))
2. Top right > **Add Files** button > **Upload files**
3. Drag your PDFs
4. Edit the commit text to explain what you did upload
5. Click **Commit changes** (keep `main` as the branch)

**Option B — Use your computer (requires git):**
```bash
cp your-publication.pdf static/pdfs/
git add static/pdfs/your-publication.pdf
git commit -m "add new publication"
git push origin main
```

### Step 3: Wait for deployment

Pushing to `main` starts an automatic pipeline, you can monitor it at the [Actions page](https://github.com/medialab/editions-annexes/actions).

The pipeline:
1. Reads the PDF metadata (title, authors, etc.)
2. Creates one JPEG image per page
3. Makes a cover thumbnail from the first page
4. Adds the publication to the website filesystem 
5. Publishes the site with the new publication

## Step 4: Editing the publication

After the first deployment, you will find in the [media folder](https://github.com/medialab/editions-annexes/tree/c398bb0044c467a76d181a520c3812cb45e0ef6b/src/lib/media/editions) one folder for each publication, the structure inside contains:

1. `canvasElements` folder - Add here all the images that should appear in the landing page
2. `images` folder - Add here all the images that should appear inside the publication (for example, photos of sessions, or stuff regarding the publication)
3. `pages` folder - All the pages of the PDF automatically generated by the script

After the automatic setup, you can edit [the datasource](https://github.com/medialab/editions-annexes/blob/c398bb0044c467a76d181a520c3812cb45e0ef6b/src/lib/data/datasource.ts) to change the visible informations of each publication.

> [!IMPORTANT]
>After modifications, **commit changes** and **push** to the main branch.

## Local Development

This website is built on [Bun](https://bun.com/), written in [Svelte 5](https://svelte.dev/) and [Tailwind CSS](https://tailwindcss.com/).
If you want you can **clone the repository**, **install bun**, and proceed **editing the code**.

### Useful Commands

| Command | What it does |
|---------|-------------|
| `bun run dev` | Start a local preview server |
| `bun run build` | Build the site for production |
| `bun scripts/process-pdf.js` | Sync PDF files with the database |
| `bun test` | Test the PDF pipeline |

Furthermore, this website:

- **No database or CMS.** Everything is file-based. The "database" is `src/lib/data/datasource.ts`.
- **PDFs go in** `static/pdfs/`. The pipeline finds new files and processes them.
- **Images are generated** into `src/lib/media/editions/<slug>/`.
- **GitHub Pages** hosts the site. Every push to `main` triggers a new build and deploy.
